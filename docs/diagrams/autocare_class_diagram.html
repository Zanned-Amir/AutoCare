Roles and permissions

OrganizationMember (embedded permissions)

No Role table. Templates live in code as MemberRoleKey. 
{
  "organizationId": 12,
  "userId": 45,
  "status": "ACTIVE",
  "roleKey": "PROVIDER_TECHNICIAN",
  "permissions": [
    "request:read",
    "request:update_status",
    "history:read"
  ]
}

How authorization works

  1. Platform endpoints (admin, own vehicles, diagnostics) check the roles and permissions in the JWT (loaded from Role through UserRole at login, so no join per request).
  2. Organization endpoints load the member by (organizationId, userId), cached in Redis as perms:{orgId}:{userId}.
  3. r:a is granted by r:a, r:*, *:a or *:*.
  4. Adding a member copies the template permissions. Editing them sets roleKey = CUSTOM.
  5. Each organization keeps at least one member with member:manage or *:*.
